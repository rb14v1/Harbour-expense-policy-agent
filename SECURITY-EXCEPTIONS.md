# Security Exceptions — Dependency CVEs

Requirement: `sec.no_critical_cves` — no dependency may carry a CRITICAL or HIGH
severity CVE that has a fixed version available. CVEs with no fix available are
recorded here as accepted risk with a justification and review date.

## Scope

| Ecosystem | Manifest | Lockfile |

| Python (backend) | `requirements.txt` | — (pins / ranges in manifest) |
| Node.js (frontend) | `frontend/package.json` | `frontend/package-lock.json` (regenerated by npm, never hand-edited) |

## Process

1. Re-run `trivy fs --scanners vuln --severity CRITICAL,HIGH .` (covers
   `requirements.txt` and `frontend/package-lock.json`) before every deployment.
2. Any CRITICAL/HIGH finding with a fixed version must be pinned to the patched
   version in `requirements.txt` or `frontend/package.json` (then regenerate the
   lockfile with `npm install`) before deployment.
3. Any CRITICAL/HIGH finding without a fix must be added to the accepted-risk
   table above with a justification and a review date no more than 90 days out.
